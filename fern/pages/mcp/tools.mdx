The [hosted MCP](./hosted-mcp.mdx) exposes the KINETK graph as tools in four groups. Tool names carry a `kinetk_` prefix so they never collide with other servers you have connected.

You rarely call these yourself — your assistant picks them. Mention **kinetk** in your prompt so it knows to.

## Context jobs — live retrieval and analysis

These run the async [intelligence jobs](../guides/intelligence-jobs.mdx) and are billed like them.

| Tool | Does | Maps to |
|---|---|---|
| `kinetk_get_context` | **The default.** Submits a job *and waits for it* (about 24 seconds), returning the result inline. If the job is still running it returns `{ status: "pending", jobId }` — keep polling with the status tool. | `POST` + `GET /intelligence/jobs` |
| `kinetk_create_context_job` | Submits a job and returns a `jobId` without waiting. For slow jobs (`window: "all"`, large pulls) or fire-and-forget. | `POST /intelligence/jobs` |
| `kinetk_get_context_job_status` | Cheap status poll: `queued`, `running`, `completed` or `failed`. | `GET /intelligence/jobs/{id}` |
| `kinetk_get_context_job_result` | Fetches a finished job's result — a slim, token-efficient envelope by default, or the full payload with `verbose: true`. | `GET /intelligence/jobs/{id}` |

The job tools take a `kind`:

| `kind` | Inputs | Returns |
|---|---|---|
| `records` | `query`, `limit` (required); `window`, `platforms` | The matching posts and videos, ranked. |
| `insights` | `query` (required); `window`, `limit`, `includeSignals`, `returnRecords`, `includeGraphs`, `platforms` | Narratives with trajectory and sentiment, tag and theme signals; written takeaways with `includeSignals`. |

Through the MCP, `limit` must be **750–10,000** — smaller pulls rarely give useful intelligence, so the tools reject them. For visual questions use `kinetk_search_patterns` below, which runs a `patterns` job.

`window` defaults to `all` when omitted. Jobs commonly take 1–3 minutes on `window: "all"` or large pulls — a long `running` is normal, not stuck. Results too large to return inline come back as `{ resultStorage: "s3", resultUrl }`.

## Narratives — the precomputed narrative map

Free, instant reads; no job, no polling.

| Tool | Does | Maps to |
|---|---|---|
| `kinetk_trending_narratives` | The top narratives for `7d` or `30d`. | `GET /narratives/trending` |
| `kinetk_search_narratives` | Narratives whose name or tags match a `query`. | `GET /narratives/search` |
| `kinetk_get_narrative` | One narrative's posts, top creators and platform split, by `id`. | `GET /narratives/{id}` |
| `kinetk_get_narrative_trajectory` | One narrative's metric history, newest first — is it accelerating or fading? | `GET /narratives/{id}/trajectory` |

Narrative ids come from trending, search, or an `insights` result.

## Patterns — the visual pattern map

| Tool | Does | Maps to |
|---|---|---|
| `kinetk_search_patterns` | **Start here for visual questions.** Finds the patterns that match a question, with their recurring elements and lookalikes. | `patterns` job |
| `kinetk_list_patterns` | Browses the map, optionally filtered by `elementType` + `elementValue` (both together). | `GET /intelligence/patterns` |
| `kinetk_get_pattern` | One pattern's full evidence by `patternKey`: elements, counts, growth, trajectory. | `GET /intelligence/patterns/{patternKey}` |
| `kinetk_get_pattern_content` | The posts inside a pattern, most representative first. | `GET /intelligence/patterns/{patternKey}/content` |
| `kinetk_get_pattern_neighbors` | Patterns that **look alike despite different tags** — the non-obvious connections. | `GET /intelligence/patterns/{patternKey}/lookalikes` |

`kinetk_search_patterns` runs a `patterns` job ($10.00); the other pattern tools are free reads.

## Search and fetch — for ChatGPT deep research

| Tool | Does |
|---|---|
| `search` | Finds content matching a query and returns lightweight results `{ id, title, url }`. Runs a 100-record `records` job (`window: "all"`), so it costs up to $1.00 per call. |
| `fetch` | Returns one result's full text and metadata by its `id`. |

ChatGPT's deep-research mode requires exactly these two names, so they are the only tools without the `kinetk_` prefix. Other assistants can ignore them.

## Example prompts

- *"Use kinetk to show what's trending in fitness this week, then drill into the top narrative."* → `kinetk_trending_narratives`, then `kinetk_get_narrative`.
- *"Use kinetk to analyze the luxury watch conversation over the last 30 days, with written takeaways."* → `kinetk_get_context` with `kind: "insights"`, `window: "30d"`, `includeSignals: true`.
- *"With kinetk, find what cozy home office content looks like and what it's visually related to."* → `kinetk_search_patterns`, then `kinetk_get_pattern_neighbors`.
- *"Pull 1,000 recent posts about sustainable sneakers from kinetk so I can cite them."* → `kinetk_get_context` with `kind: "records"`, `limit: 1000`.

## Privacy

Creator handles, display names and platform-native ids are never returned. A creator is represented by a numeric id and a `followerCount`.
