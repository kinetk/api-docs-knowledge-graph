Five minutes from `curl` to a real `intelligence_signals` result (or an `intelligence_records` download). Pick any HTTP client you like; we use `curl` here.

## Prerequisites

```bash
export API_BASE="https://api.kinetk.ai/graph"
export API_KEY="<paste your key here>"
```

If you don't have a key yet, see [Authentication](./authentication.mdx). The production base URL is `https://api.kinetk.ai/graph` — see [Introduction](../introduction.mdx#base-url).

## 1. Health check

```bash
curl -H "x-api-key: $API_KEY" "$API_BASE/health"
```

Expected response (status `200`, latency under 1 second):

```json
{
  "ok": true,
  "lastSyncedAt": "2026-04-28T17:32:11.000Z",
  "syncFreshSeconds": 1432
}
```

`syncFreshSeconds` tells you how recently the ingestion pipeline ran. Under `3600` (one hour) means data is fresh. Much higher and the hourly sync is lagging — see [Sync & Freshness](../guides/sync-and-freshness.mdx).

If you get `403 { "message": "Forbidden" }`, the API key isn't being sent — check the header name and value.

## 2. Submit an async intelligence job

The records / signals / brief / context kinds all run async because they can take 5–20 seconds. Submit returns immediately with a `jobId`:

```bash
curl -X POST "$API_BASE/intelligence/jobs" \
  -H "x-api-key: $API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "kind": "intelligence_signals",
    "input": {
      "query": "smart watch launch"
    }
  }'
```

`intelligence_signals` takes exactly one input field — `query`. Everything else (time window, scan size, platforms, query expansion) is managed by the service for this kind; sending any other field returns `400`. The other kinds (`intelligence_records`, `campaign_brief`, `llm_context`) accept filters and **require** an explicit `window` and `limit` — see [Intelligence Jobs](../guides/intelligence-jobs.mdx).

Three possible responses:

```jsonc
// Fresh submit — new work queued, credits reserved at the estimate:
{ "jobId": "0190bd6f-...", "status": "queued", "estimated_cost": 0.5, "statusUrl": "/intelligence/jobs/0190bd6f-..." }

// Cache hit — inline result (intelligence_signals / campaign_brief / llm_context):
{ "jobId": "0190bd6f-...", "status": "succeeded", "result": { /* full payload */ }, "fromCache": true }

// Dedup — identical input already running, same jobId returned:
{ "jobId": "0190bd6f-...", "status": "queued", "dedup": true, "statusUrl": "/intelligence/jobs/0190bd6f-..." }
```

Save the `jobId`:

```bash
JOB="0190bd6f-..."
```

## 3. Poll for the result

```bash
curl -H "x-api-key: $API_KEY" "$API_BASE/intelligence/jobs/$JOB"
```

Poll every 2–5 seconds until `status` flips from `queued` → `running` → `succeeded`. Typical end-to-end time for `intelligence_signals`: 5–20 seconds.

```jsonc
// While running:
{ "jobId": "0190bd6f-...", "kind": "intelligence_signals", "status": "running", "submittedAt": 1745859300, "startedAt": 1745859302 }

// When done (intelligence_signals — result is inline):
{
  "jobId": "0190bd6f-...",
  "kind": "intelligence_signals",
  "status": "succeeded",
  "submittedAt": 1745859300,
  "startedAt":   1745859302,
  "completedAt": 1745859318,
  "charged": 0.5,
  "result": { /* signals payload — see API reference */ }
}
```

### `intelligence_records` — download the result from the URL

For `intelligence_records` jobs, the succeeded response carries a `resultUrl` instead of an inline `result`. The URL is a presigned S3 link — download it with a plain GET (no `x-api-key` header needed):

```jsonc
// When done (intelligence_records — download envelope):
{
  "jobId": "0190bd6f-...",
  "kind": "intelligence_records",
  "status": "succeeded",
  "submittedAt": 1745859300,
  "completedAt": 1745859490,
  "charged": 12.5,
  "actualRecordsReturned": 4812,
  "resultUrl": "https://kinetk-intelligence-job-results-….amazonaws.com/jobs/0190bd6f-….json?X-Amz-…",
  "resultBytes": 18234567,
  "resultExpiresAt": 1745860390
}
```

```bash
# Save to file:
RESULT_URL=$(curl -s -H "x-api-key: $API_KEY" "$API_BASE/intelligence/jobs/$JOB" \
  | jq -r '.resultUrl')
curl -o result.json "$RESULT_URL"

# Or pipe directly into jq:
curl -s "$RESULT_URL" | jq '.content | length'
```

The URL expires ~15 minutes after it was issued (`resultExpiresAt`). A fresh URL is minted on every poll, so if you get a `403` from S3, re-poll the status endpoint and use the new `resultUrl`. Do not cache the URL — cache the downloaded JSON instead.

## 4. Skip the polling — use the MCP

If you'd rather have Claude or Cursor handle the submit/poll loop for you, install the `kinetk` MCP server — see [MCP Installation](../mcp/installation.mdx). The MCP exposes the same `intelligence_signals` flow as a one-tool call with built-in polling and a slim, token-efficient response envelope.
